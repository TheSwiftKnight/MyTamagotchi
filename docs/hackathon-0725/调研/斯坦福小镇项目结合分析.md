## 〇、一句话结论(Rev 2 · 方向定案)

**以 generative_agents 为基座,三个用途**:① **P0 演出层基座**——它的 demo 前端直接当「使者访问演出」渲染器,后端只需把 VisitResult 转成 `master_movement.json`(**已端到端验证通过**,见下);② **P1 内容工厂**——reverie 引擎离线跑每个用户的世界(接 GLM/DeepSeek 兼容端点),给世界预生成「生活痕迹」,卡在预生成铁律内;③ **P2 摊位叙事**——左屏斯坦福原版小镇 vs 右屏我们的世界,零开发量。其余 90% 的代码(实时轮询、寻路、日程规划)与我们的产品形态不匹配,不值得碰。

> Rev 2 验证记录(2026-07-23):转换器 `server/visit_to_master_movement.py` 已落地,用 contracts 冻结的 VisitResult + WorldJSON 样例生成 247 步演出,在斯坦福前端 `http://localhost:8100/demo/world_visit_demo/1/3/` 实际播放成功——使者从入口逐地标行走、到位冒 15 字气泡、结尾亮契合度金句,全程零新增前端代码。

## 一、架构对比:为什么是「抽取」而不是「整合」

| | 斯坦福 reverie | 世界互访(我们) |
|---|---|---|
| 场景 | 25 agent 公共小镇,实时自主生活 | 1 使者访问 1 个私人世界,30 秒脚本化演出 |
| 驱动方式 | 前端推坐标→后端 LLM 决策→写 movement→前端执行,每步 2~8 次 LLM 调用 | 碰时生成 / 预生成缓存,两次 LLM 调用 |
| 地图 | Tiled JSON(渲染)+ matrix CSV 五件套(语义寻路) | Tiled JSON + Easystar,地标列表顺序遍历 |
| 前端 | Phaser 3.55,逐帧手写位移 | Phaser 3.80,Tween + Easystar |
| 状态同步 | **文件系统即消息队列**(environment/movement JSON) | WebSocket + MQTT |

关键判断:reverie 的核心复杂度(实时多 agent 调度、寻路、日程分解)解决的是我们**没有**的问题;它的精华(记忆、prompt 工程、回放演出)恰好是我们**还差**的。和林亦团队的教训一致——他们看完代码也放弃了改造,选择自研;但我们可以比他多抽走三样零件。

## 二、P0·立即可用(本周就能进代码)

### 1. Prompt 工程的 validate/clean_up/fail_safe 四件套

reverie 里唯一生产级的设计,`run_gpt_prompt.py`(2930 行)每个生成函数固定四件套:

```
create_prompt_input → GPT 调用 → __func_validate(校验输出格式)
→ 失败重试 ≤5 次 → __func_clean_up(清洗) → 全挂返回 get_fail_safe(硬编码兜底)
```

- 出处:`reverie/backend_server/persona/prompt_template/gpt_structure.py:123`(ChatGPT_safe_generate_response)、`:255`(safe_generate_response)
- 行动:把这套签名套到我们现有的 Call 1(游记)和 Call 2(契合)上。我们目前只有「JSON schema 校验失败重试 1 次→20 组兜底」,缺中间的 clean_up 层(比如从模型输出截取到最后一个 `}` 再解析的容错)。**半天工作量,直接提升防翻车体系的第二级。**

### 2. demo 回放架构 + master_movement.json 契约(✅ 已验证落地)

它的大屏 demo 不轮询:`demo()` 视图(`translator/views.py:26-98`)把压缩后的 `master_movement.json`(所有步合并)一次性塞进页面,前端纯本地按步播放。**与我们「预生成演出」完全同构。**

## 三、P1·差异化能力(常驻互访与契合度的升级)

### 4. 记忆检索打分公式(50 行可移植)

`cognitive_modules/retrieve.py:new_retrieve`(行199):

```
score = 0.5×recency_norm + 3.0×relevance_norm + 2.0×importance_norm
recency 衰减 0.99^i;relevance = 焦点文本 embedding 与记忆节点余弦相似度
```

- 用途 A(契合度升级):现在 Call 2 的契合度是 LLM 拍脑袋打分。可以先把两份 WorldJSON 的地标/住民文本做 embedding,用这个公式算一个**可解释的语义共鸣分**作为 LLM 打分的参考输入——「契合度不是拍脑袋,是 0.5/3/2 加权的 embedding 检索分 + LLM 解释」这句话可以直接讲给评委
- 用途 B(常驻互访的记忆):使者第二次访问同一世界时,用该公式从「上次游记记忆」里检索相关条目,生成「上次我来的时候……」的连续性——这是斯坦福论文验证过的最强体验点,也是没人做过的差异化
- 移植注意:`gpt_structure.py` 的 embedding 调用是 openai 0.x API,需升到 1.x(或换成本地 embedding 模型)

### 5. 「对话→摘要→带证据回溯」的游记落库模式

`converse.py` + `reflect.py:190`:对话结束后生成 planning_thought + memo_thought 两条摘要写入记忆,带 evidence 指针指回原始对话节点。

- 行动:游记 JSON 里加 `evidence: [引用的地标 slot]` 字段,常驻互访时新游记可引用旧游记节点——廉价实现「使者记得上次」
- 出处:`reverie/backend_server/persona/cognitive_modules/reflect.py:190`、`converse.py:agent_chat_v2`

### 6. 造物主调试页(半天做一个)

`replay_persona_state`(`translator/views.py:186-232`):纯模板渲染的 persona 状态页——身份、日程、记忆流(event/chat/thought 三栏)。60 行视图 + 200 行模板。

- 行动:Day 4 防翻车日做一个我们自己的版本:展示使者的 WorldJSON、当次 visit 的 bubbles/travelogue、预生成命中率。摊位联调时极大提升排障效率;demo 时也可以作为「拆开给评委看使者内心」的隐藏高光(林亦视频证明过这是爆款点)

## 四、明确不搬的(避免被拖进泥潭)

| 部件 | 为什么不要 |
|---|---|
| process/update/execute 三段轮询状态机 | 为实时 LLM 模拟设计,文件 IPC + 每步 2~8 次 LLM 调用,与「预生成演出」目标相反 |
| `maze.py` / `path_finder.py` / matrix CSV 五件套 | 我们的「移动」是地标列表顺序遍历 + Easystar,不需要语义迷宫 |
| `plan.py`(日程分解/反应/对话调度) | 缠在一起 + 硬编码日期,重写的功夫比自研还大 |
| `execute.py` | 含未捕获的故意报错(学术代码原样) |
| `reverie.py` 主进程 | 依赖 selenium + 文件轮询,与 FastAPI 架构不兼容 |
| 25 人侧边栏/键盘控制等 home 页 UI | 与单使者小地图场景不匹配 |

## 六、给 pitch 的一句话

> 斯坦福证明了 agent 能有记忆和社交,但他们的小镇需要每步 2~8 次 LLM 调用、25 人一天上万次——我们把它的记忆检索公式和演出架构抽出来,压进两次调用和 30 秒里,让「agent 替真人社交」第一次能跑在 90 秒的 hacker 现场。
