隐蔽陷阱 · 读卡器读不了读卡器

两台 M5Dial 互碰不会有任何反应——WS1850S 是 Reader，Reader 无法读 Reader。解法（Tagging Hack）：每台设备背面贴一张 ¥0.5 的无源 NTAG213 贴纸。A 的正面（读卡区）碰 B 的背面，读到的是 B 的唯一 ID 标签。「碰一碰」的方向性要在工业设计里画清楚。

09.3手机侧：iOS 小程序 HCE 是死路，扫码 H5 是活路

微信小程序能力真相：Android 蓝牙/NFC/HCE 全支持；iOS 蓝牙可用、NFC 读标签可用（iPhone 7+）、HCE 彻底不支持（微信官方明确声明）。「用手机模拟卡去碰硬件」这条线上所有 iOS 用户全灭。原生 App 则死于 TestFlight 审核与现场装包耐心。推荐架构：硬件屏幕显示动态二维码 → 微信扫一扫 → 云端 H5 → WebSocket 连服务器 → 服务器经 MQTT 下发硬件指令——「虚假的物理直连，真实的云端互通」，全平台一致、120 小时内成功率最高。

09.4Agent 层：最小可行架构（MVA）

框架模式黑客松判词
裸 LLM ×2 + JSON无框架推荐 唯一能保证 100% 演示成功率的方案
OpenAI Agents SDKHandoffs最易上手但厂商锁定；本场景仍嫌多
CrewAI角色流水线DX 好，但重试/干预一复杂就崩
AutoGen会话协商发散难控，token 开销不可预测
LangGraph状态图过度设计 学习曲线 1–2 周
A2A / MCP互操作协议答非所问：MCP 管工具调用，A2A 对两人 demo 过重

两步编排：Call 1（GPT-4o-mini 级快模型）输入双方画像 → 找 3 个维度共同点；Call 2 强制 response_format: json_object → 一次性输出 dialogue_history（agent 对话稿）+ summary + hardware_feedback（LED 色值、蜂鸣节奏）。剥夺 agent 的「自由意志」，换来演示的确定性。

画像构建同样做减法：不搭向量库。用户贴个人主页 URL → Jina Reader（r.jina.ai/ 前缀）清洗成干净 Markdown → LLM 零样本抽取 [职业, 兴趣, 性格, 价值观] JSON → 存 Redis。几十人规模下，LLM 直接推理的语义深度（知道「儿科医生」和「资深护士」是好话题搭子）碾压余弦相似度。

09.5Demo 防翻车 Checklist

  • 预生成：用户扫码注册排队时，云端已开始生成两人的对话 JSON；真正碰的瞬间只是拉取缓存——任何「现场实时生成」都是高危动作
  • 三级降级：云端超时 5 秒 → 从 20 个硬编码优质结果里随机返回；硬件 3 秒无响应 → 播放本地固化的应急动画（高匹配/普通/失败三套），保证宠物「永不僵死」
  • 自带 5GHz 路由器：后台服务与手机全部走自带路由，避开会场 2.4GHz 修罗场；ESP-NOW 锁冷门信道
  • 静态 H5 兜底：后端全宕时扫码仍跳转到写好幽默话术的静态页（「AI 智能体正在咖啡休克中」）
  • 硬件后备 ×3：烧录相同固件的备机 ≥3 台，现场不修 bug 只换机
  • 缓冲动画：「神经元计算中…」转场 4–5 秒，为网络重试争取时间掩护

11.1一句话定位

Pitch · 第一句话

你和 TA 的宠物碰了一下——三秒后，它们已经替你们聊完了第一轮：屏幕上是你们真正值得开口的那句话。

叙事顺序：一个具体的尴尬瞬间（在 AdventureX 排队，想认识旁边的人却不知道说什么）→ 碰一碰 → 同频呼吸灯亮起 → 念出屏幕上那句破冰词。全程不出现「协议」「架构」等词，技术留给追问环节。
