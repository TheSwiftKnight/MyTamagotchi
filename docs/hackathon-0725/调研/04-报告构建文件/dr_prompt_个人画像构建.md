# Deep Research 调研任务：从 URL/PDF 快速构建用户个人画像的模块设计

我们在做一个 4 人 × 4 天黑客松（AdventureX）项目「世界互访」：线下 NFC 碰一碰社交产品，云端根据每个用户的**个人画像**生成专属虚拟世界（世界名、气候、地标、居民），并驱动一个代表用户的「使者」Agent 与对方世界互动、生成游记和契合度评分。

现在需要你**只聚焦调研一个模块：用户个人画像（自我介绍）的自动化构建**。

## 模块背景

- 用户可以手写自我介绍，但为了**快速体验**，我们提供一个快速通道：用户只需扔进来**一个或多个 URL**（个人主页 / GitHub / 微博 / 知乎 / 公众号文章 / 作品集网站）或**一个 PDF 文件**（简历、个人介绍、作品集），系统自动在 30 秒内构建出一份结构化个人画像。
- 画像的下游消费者有三个：① LLM 生成虚拟世界（需要从 30 种预制地标类型中选择并命名）；② LLM 扮演用户的「使者」Agent 去别人世界里访问、对话、写游记（需要知道语气、性格、兴趣）；③ 计算两人「灵魂契合度」（需要可比较的兴趣/价值观标签）。
- 团队里正在争论画像的身份 Schema：有人提出分级（用户本人=king/star 唯一、使者=envoy、百姓=npc 不可直接互动），有人关心角色是否可自定义、世界历史/人物关系/聊天历史/游记怎么存储（是否上 GraphRAG）、来访 Agent 的可见范围、世界是可视化地图还是纯文字。这些争论的根子都是「画像到底长什么样、包含什么、怎么存」。

## 请调研的问题

1. **个人画像 Schema 设计**：业界 persona/数字分身产品（Character.AI、Replika、Delphi、Personal AI、Spheria、HeyGen 数字人、各种 AI clone 产品）以及学术论文（persona extraction、user profiling from social media、LLM role-play agent 的 persona 设计，如 CharacterLLM、RoleLLM、Generative Agents 的 memory stream）里，一个"能驱动角色扮演 + 支撑推荐/匹配"的用户画像通常包含哪些字段维度（身份事实、兴趣标签、价值观、语言风格、关系、记忆…）？给出你推荐的、适合我们下游三个消费者的**最小可用 Schema v1**（具体到字段名、类型、示例）。
2. **从非结构化来源提炼画像的 pipeline**：从社交主页 URL / PDF 简历 / 多篇混合来源构建画像的成熟做法——抓取与清洗（Jina Reader、PDF 解析工具对比）、多来源融合与去重、每条事实的**来源溯源（provenance/citation）**、置信度标注。有没有现成的开源项目或论文 pipeline 可参考（如简历解析工具、persona extraction 数据集与方法）？
3. **防幻觉与事实核查**：画像事实编造是最大质量风险。业界/学界怎么做：逐条引用原文、抽取式 vs 生成式、两阶段（先抽事实再写叙述）、LLM-as-judge 校验、以及**用户确认环节（human-in-the-loop）**的产品设计——快速体验场景下，确认步骤怎么设计才不破坏流畅感（如生成后让用户一键删改 3 个标签）？
4. **冷启动与渐进式丰富**：30 秒内先给骨架画像、之后随使用逐步丰富的"渐进式 profiling"产品设计案例；冷启动时信息极少（如一个几乎空白的 GitHub 主页）时画像怎么兜底（主动提问补全？模板化？）。
5. **画像 → Agent 角色扮演的落地**：画像如何编译成使者 Agent 的 system prompt？风格模仿（说话像本人）需要多少语料、什么技术（few-shot 摘录原文金句 vs 风格摘要）？游记写作时如何让使者"知道什么能说什么不能说"（隐私边界/可见范围，对应团队争论的"来访可见范围"）？
6. **存储与扩展**：画像本身 + 世界历史时间线 + 人物关系 + 聊天记录 + 互访游记，在黑客松尺度（100 用户、几百次互访）下，SQLite/JSON 文档存储是否足够？GraphRAG / 知识图谱在什么规模才真正必要，现在上的话成本收益如何？
7. **隐私与合规红线**：抓取用户自己提供的 URL 构建画像的授权边界；如果用户提交的是**别人的**主页 URL 怎么办；微信生态内 H5 收集这些信息要注意什么。

请输出一份中文深度调研报告：每个问题给出结论 + 可执行建议 + 具体来源引用；最后附一份「画像 Schema v1 字段表」和「构建 pipeline 流程图（文字版）」。
