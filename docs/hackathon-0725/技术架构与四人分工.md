## 〇、先说一个重要的架构修订（RFC-1）

**Rev B 之后，AI Town + Convex 不再是最优解，建议改为 Phaser 3 自建。**

理由：AI Town 的核心价值是「一个公共小镇里多个 agent 实时自主活动」——那是 Rev A 的需求。Rev B 的世界是**每人一张独立小地图 + 使者按脚本走一圈**，根本不需要实时多智能体自主行为，也就不需要 Convex 的实时状态同步。继续 fork AI Town 等于背着它最大的坑（Convex 学习曲线，评估要吃掉 1.5 天）去换一个用不上的能力。

| | Fork AI Town（原 Rev A 路线） | **Phaser 3 自建（Rev B 推荐）** |
|---|---|---|
| 匹配度 | 为「公共镇多 agent 自主」设计，Rev B 用不上 | 「单地图 + 脚本化演出」正是 Phaser 的甜区 |
| 最大风险 | Convex Serverless 学习曲线（1.5 天） | 无框架绑定；寻路用 Easystar.js 现成库 |
| 动画自由度 | 受 pixi-react 封装限制 | 生成动画/使者演出完全可控（Tween 即可） |
| AI 代码辅助 | Convex 语料少 | Phaser 语料全网最丰富，AI 生成准确率最高 |
| 失去什么 | — | agent 自主闲逛（P1 常驻互访改为「每日定时生成动态」即可，无感知差异） |

**决策：P0 用 Phaser 3 + Tiled + Easystar.js；AI Town 仓库留作参考不 fork。** 若 Day 1 结束发现需要真自主行为再回头，但按 P0/P1 范围判断不会。

> 连带简化：Rev B 的 P0 也不需要 ESP-NOW（在场感知是 P1）。P0 的硬件通信只剩 MQTT 一条,固件复杂度下降一档。

## 一、四人分工

按三次录音里明确的技能牌面对号入座（名字你们自己填）：

| 代号 | 技能背景（来自讨论） | 负责 | P0 交付物 |
|---|---|---|---|
| **A · 后端与 Agent** | 大模型方向 | 云端服务全部：世界生成、互访游记、灵魂契合三类 LLM 编排；预生成与缓存；REST/WS/MQTT 下发 | 可部署的后端 + 三类 Prompt（各带 3 个 few-shot）+ 20 组兜底数据 |
| **B · 前端与世界** | 做过异星工厂式产线游戏、PS 动画 | Phaser 世界渲染、**世界生成动画**、**使者互访演出**、H5（建世界页 + 游记卡片）、摊位大屏 | 世界渲染器 + 两大高光动画 + H5 全流程 |
| **C · 硬件与固件** | 计算机视觉方向（健身助教获奖）——嵌入式门槛为 Arduino 级，可承接；手势识别是他的 P1 余量 | M5Dial 固件全套：NFC 读贴纸、WS2812 灯效、屏显使者动画、MQTT 客户端、本地兜底动画；现场网络（5GHz 路由） | 3 台同版固件板子 + 三套应急动画 + 断网自测通过 |
| **D · 产品·设计·叙事** | 产品/文学强 | 使者 IP、30 种地标素材、Tiled 世界模板地图、pitch 与摊位物料、Day 1 现场调研、**每日验收官** | 素材包 + 地图 JSON + demo 剧本卡 + 四赛道材料 |

分工三原则：

1. **接口冻结换并行**：Day 0 冻结第三节的全部接口契约后，四人互不阻塞；改接口必须四人同意。
2. **B 是关键路径**：两大高光动画全在 B 手里，工时最重。C 的固件在 Day 2 跑通后，C 转为 B 的副手（素材接入/大屏页）；手势迎宾只在一切就绪后才做。
3. **D 是验收官**：每天按「当日验收标准」验收，不达标当晚砍需求——砍的权力给 D，避免工程师舍不得。

## 二、难点 Top 8（按杀伤力排序，每条带负责人与对策）

| # | 难点 | 为什么难 | 对策 | 负责 |
|---|---|---|---|---|
| 1 | **世界生成质量不稳定** | LLM 自由发挥会产出尬名字/幻觉地标，世界不像「那个人」 | 地标从 30 种预制类型里「选择+命名」，禁自由生成；温度调低；3 个 few-shot 精修范例；世界名限 8 字；20 组人工精修兜底 | A |
| 2 | **前端动画工作量爆炸** | 生成动画 + 互访演出 + H5 三线并行，是全项目最大工时块 | 素材管线 Day 0 就绪（D 出素材，B 只写逻辑）；动画全用 Phaser Tween 不写帧动画；演出严格 ≤30 秒 | B（C Day 2 后增援） |
| 3 | **预生成的 N² 组合爆炸** | 现场 100 人 = 4,950 对互访，不可能全预生成 | 改「碰时生成」：NFC 触发即调 LLM，用 20–30 秒互访演出动画做延迟掩护；已生成对子进 Redis 缓存；摊位排队的人优先预生成 | A |
| 4 | **双板同频呼吸灯** | 「同频」是灵魂契合的物理显影，两板不同步就穿帮 | MQTT 同一条 cmd 广播给两台设备，带 `epoch_ms` 起始时间戳，固件按时间戳对齐呼吸相位；时钟用 NTP 校一次 | C |
| 5 | **NFC 读卡器读不了读卡器** | 两台 M5Dial 互碰无反应（Reader 无法读 Reader） | 每台背面贴 NTAG213（¥0.5）；碰法固定为「A 正面碰 B 背面」；外壳设计画出方向指引 | C + D |
| 6 | **微信 webview 兼容** | H5 跑在微信内，API 受限 | 只用 WebSocket + 普通 DOM/Canvas（Phaser 兼容微信 webview）；不用任何需要授权的浏览器 API；静态兜底页 | B |
| 7 | **现场射频地狱** | 2.4GHz 拥挤导致 MQTT 掉线 | 自带 5GHz 路由器组独立局域网；板子 3 秒收不到 cmd 自动播本地兜底动画（永不僵死） | C |
| 8 | **90 秒讲不完三个高光** | 评委耐心有限，「参观」比「给答案」多一步 | 游记卡片先给结论（契合度+那句话）再给正文；彩排 ×3 掐表；30 秒电梯版单独准备 | D |

已消除的原头号难点：~~Convex 学习曲线~~ —— 被 RFC-1 架构修订直接删除。

## 三、技术架构（具体到接口）

### 3.1 组件总览

```
┌─ 用户手机（微信扫码 H5）─────────────┐
│  建世界页 / 游记卡片页（Phaser+DOM） │◄──WebSocket──┐
└──────────────────────────────────────┘              │
                                                      │
┌─ 摊位大屏（浏览器全屏）──────────────┐              │
│  世界渲染器 + 生成动画 + 互访演出     │◄──WebSocket──┤
│  （Phaser 3 + Tiled JSON + Easystar）│              │
└──────────────────────────────────────┘              │
                                              ┌───────┴────────┐
┌─ M5Dial ×2（碰一碰双方）─────────────┐      │   云端服务      │
│ 固件模块：                            │      │ FastAPI(Python) │
│  nfc_task     读 NTAG213 UID          │─MQTT─►  or Express     │
│  led_task     WS2812 呼吸/相位对齐    │◄MQTT─│  Redis（缓存/队列）│
│  ui_task      屏显使者动画/二维码      │      │  SQLite（落盘） │
│  net_task     Wi-Fi + MQTT + NTP      │      │  EMQX（MQTT）   │
│  fallback     3s 无响应播本地动画      │      └───────┬────────┘
└──────────────────────────────────────┘              │
                                              ┌───────┴────────┐
                                              │   LLM 层        │
                                              │ 主备两家云端 API │
                                              │ + 本地 Ollama    │
                                              │  (Qwen2.5-3B     │
                                              │   预生成评论池)   │
                                              └────────────────┘
```

技术栈定版：后端 **FastAPI + Redis + SQLite + EMQX（免费档）**；前端 **Phaser 3.80 + Tiled 地图 JSON + Easystar.js**；固件 **Arduino (ESP32-S3) + PubSubClient(MQTT) + FastLED + Adafruit_PN532/内置 WS1850S 驱动**；部署：一台云服务器（或内网笔记本 + 5GHz 路由，现场推荐后者——彻底不依赖外网，LLM 走手机热点出口）。

### 3.2 接口契约（Day 0 冻结，改动需四人同意）

**REST（A 提供，B 消费）**

| 方法 | 路径 | 入参 | 出参 |
|---|---|---|---|
| POST | `/profile` | `{url, nickname?}` | `{user_id, world: WorldJSON}`（30 秒内） |
| PATCH | `/world/{user_id}` | `{world_name?, landmark_swap?}` | `WorldJSON`（世界编辑最小版） |
| POST | `/bump` | `{uid_a, uid_b}`（NFC UID） | `{visit_id}`（立即返回，后台生成） |
| GET | `/visit/{visit_id}` | — | `{status, travelogue_a, travelogue_b, resonance}` |
| WS | `/ws/{user_id}` | — | 推送 `visit_ready` / `world_ready` 事件 |

**WorldJSON（世界元素）**

```json
{
  "world_name": "≤8字",
  "climate": "一句话", "temperament": "一句话",
  "landmarks": [{"type": "枚举30选1", "name": "≤12字", "from": "画像字段", "slot": 0}],
  "residents": [{"name": "", "personality": ""}]
}
```

**VisitResult（游记 + 契合）**

```json
{
  "bubbles": [{"slot": 0, "text": "≤15字气泡"}],
  "travelogue": "≤150字",
  "resonance": {"score": 0, "line": "一句话共鸣解释", "opener": "值得聊的那件事"},
  "hardware_feedback": {"led_rgb": "#RRGGBB", "pattern": "breath|pulse|calm", "epoch_ms": 0}
}
```

**MQTT 主题（A 发，C 收；QoS 1）**

| 主题 | 载荷 | 说明 |
|---|---|---|
| `dev/{device_id}/cmd` | `{anim: "depart|return|idle|match", led: {...hardware_feedback}}` | 双板同步：同一条消息发两台，按 `epoch_ms` 对齐相位 |
| `dev/{device_id}/evt` | `{nfc_uid, ts}` | 板子读到贴纸即上报 |
| `dev/{device_id}/hb` | `{rssi, battery}` | 心跳，摊位监控页用 |

### 3.3 碰一碰时序（P0 主链路，共 10 步）

```
1  C板A 读到 B 的 NTAG213 UID ──► MQTT evt 上报
2  A服务 查 UID→user 映射，命中缓存？──有→跳 6
3  无缓存：并发发起 Call1×2（双向游记）+ Call2（契合）
4  同时 MQTT cmd→双板：播「使者出发」动画（20–30s 延迟掩护）
5  大屏 WS 收到 visit_start：演出「使者走进对方世界」（B 的预生成气泡逐个冒）
6  LLM 返回 → 校验 JSON schema → 失败重试 1 次 → 再失败取 20 组兜底
7  结果写 Redis + SQLite，WS 推 visit_ready
8  H5 弹游记卡片（先结论后正文）
9  MQTT cmd→双板：同频呼吸（同一 epoch_ms）
10 若 3s 内板子无任何 cmd：固件自动播本地兜底动画（永不僵死）
```

### 3.4 各人 Day 0–1 的第一行代码

- **A**：`POST /profile` 打通 Jina Reader → LLM → WorldJSON（先跑通 3 个真实主页）；EMQX 起起来
- **B**：Tiled 空地图 + Phaser 渲染 + 一个 sprite 用 Easystar 从 A 点走到 B 点冒一个气泡——这一步通了，两大高光就只是堆料
- **C**：M5Dial 读 NTAG213 打印 UID + MQTT 收 cmd 点亮灯环 + 呼吸相位对齐 demo
- **D**：30 种地标素材裁切完 + 模板地图画完（Tiled 三层）+ few-shot 范例世界 3 个（和 A 一起写）
