## 〇、一分钟读懂这版和上一版的区别

| | Rev A（明星宠物·经纪人） | **Rev B（世界互访）— 终版** |
|---|---|---|
| 核心空间 | 所有 agent 住在一个公共小镇 | **每个人创造并拥有自己的世界** |
| 社交形态 | 两个 agent 站在路上聊天 | **碰一碰 = 互派 agent 到对方的世界做客参观** |
| 自我介绍 | agent 转述主人的画像 | **世界本身就是自我介绍**——你的经历、性格、审美封存在你建的世界里 |
| 匹配定义 | 共同点匹配 | **灵魂契合**——两个世界的共鸣度 |
| 隐私逻辑 | 画像脱敏 + 白名单 | **根本性解决**：不愿直接吐露自己的人，用「我创造的世界」代言自己 |
| 保留不变 | 硬件宠物載体、碰一碰触发、预生成工程、防翻车体系、赛道策略 | 全部继承 |

**为什么这版更好**（三条依据，全部有调研背书）：

1. **隐私悖论被优雅化解**。调研 HCI 结论：直接说破个人信息会引发自我展示焦虑，「信息稀缺设计」反而激发对话。「参观世界」是终极的信息稀缺设计——了解一个人，但他一个字的个人信息都没直接给你。
2. **创造性表达是这届人群的母语**。Bonjour（个人说明书）的原始动机就是「帮不擅长开口的创作者展示自己」；「建世界」把它推到极致——世界即名片。
3. **游戏化互动天然成立**。「派使者出访」「收到游记」「世界生成动画」都是游戏语言，继承了 StreetPass 收集机制与「围观自己 agent」的验证过的乐趣（SocialAI 周留存 62%）。

## 一、产品定义（终版）

### 1.1 一句话

**你的世界，就是你的自我介绍。** 每个人用 AI 创造一个属于自己的小世界；碰一碰，你们互派自己的 agent 到对方的世界里游历——它带回来一份游记，和一个答案：你们的灵魂，契不契合。

### 1.2 核心概念

- **世界（World）**：你的性格、经历、审美的映射与延伸。由你的画像自动生成 + 你手动自定义（地标、住民、天气、气质）。你不必说「我是谁」——你的世界替你说。
- **使者（Envoy）**：你的 agent 宠物。平时住在你的世界里；碰一碰后被「派往」对方的世界做客。
- **游记（Travelogue）**：使者从对方世界回来后的汇报——「他的世界里有一座通宵亮灯的实验室，和你后院那台失眠的机器是同一种孤独」。破冰素材从「共同标签」升级为「世界见闻」。
- **灵魂契合度（Soul Resonance）**：两个世界元素的语义共鸣评分 + 一句话解释。不是「你们都喜欢 Python」，而是「你们的世界都把『未完成的东西』放在最显眼的位置」。
- **硬件宠物**：世界的「门牌 + 大使馆」。屏幕上是你的使者；有访客来你世界时它会亮灯提醒；灵魂契合时两台设备同频呼吸。

### 1.3 核心循环（用户旅程）

```
① 建世界（首次 90 秒）
   扫码 → 贴主页 URL → LLM 生成世界初稿（世界生成动画 = 第一个「哇」时刻）
   → 可手动改：起名、换地标、调气质
② 碰一碰（线下相遇）
   NFC 触发 → 双方 agent 互访对方世界（屏上演出「出发」动画）
③ 游记回报（30 秒后）
   H5 收到使者游记 + 灵魂契合度 + 「你们值得聊的那件事」
   两台硬件同频呼吸灯 = 灵魂契合的物理显影
④ 回访与沉淀
   契合的人可以「常驻互访」——你的使者会定期去朋友的世界串门，带回新鲜事
```

### 1.4 与友念（2025 第一名）的关系——答辩必讲

友念给你一个光信号说「他和你是同类」；我们让你走进他亲手创造的世界，再告诉你你们为什么是同类。**主动对标，不回避。**

### 1.5 候选名（现场定）

小世界 / 界界 / 灵契 / Worldy —— 原则：能当动词用（「来我世界看看」）。

## 二、系统架构（终版）

```
[NTAG213 贴纸/硬件背贴] --NFC 碰一碰--> [读到对方 world_id]
        |                                    |
        v                                    v
[手机扫码 H5（微信内）] <--WebSocket--> [云端服务] <--MQTT--> [硬件板子 M5Dial]
        |                                    |                 (使者形象 + WS2812 灯环)
        v                                    v
[世界生成: 主页URL → Jina Reader → LLM →     [互访编排: 两次 LLM 调用 + JSON
 世界元素 JSON（地标×6/住民×2/气质/天气）]      → 游记 + 契合度 + 硬件指令]
                                             |
                                             v
                ext[世界渲染: AI Town fork——每用户一张小地图实例
                    （模板地图 + 按世界元素 JSON 摆放地标/住民）]
```

### 2.1 五条铁律（继承 Rev A，口径不变）

1. NFC 只做触发（传 world_id），数据走云端——别说「离线 agent 对话」
2. Agent 层两次裸 LLM 调用 + `response_format: json_object`，不上框架
3. 设备互发现 ESP-NOW 广播（锁冷门信道、3 连发去重）
4. 全平台统一「硬件屏显二维码 → 微信扫码 → H5」（iOS 小程序 HCE 是死路）
5. 演示内容全部预生成缓存；三级降级兜底

### 2.2 「世界」的工程化定义（新增，5 天可实现的关键）

**世界 = 模板地图 × 世界元素 JSON。** 不做自由建造（工程灾难），做「生成 + 换装」：

```json
{
  "world_name": "熬夜实验室",
  "climate": "常年凌晨三点，星光很好",
  "temperament": "安静但门永远开着",
  "landmarks": [
    {"type": "lab", "name": "通宵亮灯的实验室", "from": "职业:嵌入式工程师"},
    {"type": "shelf", "name": "堆着 47 个烂尾项目的架子", "from": "兴趣:side project"},
    {"type": "statue", "name": "第一块点亮的开发板纪念碑", "from": "经历"}
  ],
  "residents": [
    {"name": "看门的猫", "personality": "替主人挡掉无聊的访客"}
  ]
}
```

- 渲染：一张 LimeZu 模板地图 + 6–10 个可替换的地标贴图槽位（预备 30 种地标素材，LLM 只做「选择 + 命名」，不做生成图片）
- **世界生成动画**：地标逐个「长出来」+ 名字浮现（参考录音里提到的城市生成动画）——这是 demo 的第一个高光，R2 重点打磨
- 互访：对方使者的 sprite 在你的地图上按地标路径走一圈，每到一个地标头顶冒一句评论（预生成），全程 20–30 秒——**这就是可围观的「参观」**

### 2.3 游记与灵魂契合的生成（两次 LLM 调用的新 Prompt 设计）

- **Call 1（互访游记）**：输入 = 访客画像 + 主人世界元素 JSON → 输出 = 使者在每个地标前的评论（气泡词）+ 游记正文（150 字内）
- **Call 2（灵魂契合）**：输入 = 两份世界元素 JSON → 输出 = 契合度（0–100）+ 一句话共鸣解释 + 「值得聊的那件事」+ `hardware_feedback`（灯色/节奏）
- 红线继承：只引用「世界元素」，不引用画像原文——**世界是防火墙，隐私不穿透**

## 八、风险与红线（终版增补）

- 🔴 **世界生成质量不稳定**（新增，终版最大风险）→ 地标只做「30 选 N + 命名」不做自由生成；20 组精修兜底世界；Prompt 里给 3 个 few-shot 范例
- 🔴 被指友念 2.0 → 主动对标（1.4 的话术）
- 🔴 现场翻车 → Day 4 全套 + 备份视频
- 🟡 **「参观世界」比「直接给答案」多一步，评委没耐心**（新增）→ 互访演出严格 ≤30 秒；H5 游记先给结论（契合度+那句话）再给正文
- 🟡 内容冒犯/尬 → 游记只引用世界元素不引用画像原文；尴尬时使者背锅（「使者今天导航失灵了」）
- 🟡 技术叙事被问穿 → 口径不变：「近场做发现与握手，智能在云端」
- ⚪ 评审随机性 → 四赛道全投；**Rev A 回退开关保留到 Day 1 结束**
